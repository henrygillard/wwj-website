## Image Embedding Contract

This section is specific to Phase 3. It governs how every `<img>` element must be written after the WebP migration.

### Rule 1: All img elements must carry explicit width and height attributes

Width and height attributes must reflect the **intrinsic dimensions of the output WebP file** (post-resize), not CSS display dimensions. This is what allows the browser to compute aspect ratio before the image loads, preventing CLS.

| Image location | intrinsic width | intrinsic height | Notes |
|----------------|----------------|-----------------|-------|
| Gallery images (barton-springs DSC*) | 800 | calculated by sharp (fit: inside) | height varies per image; emitted by convert-images.mjs |
| Gallery images (radio-east DSC*) | 800 | calculated by sharp (fit: inside) | height varies per image; emitted by convert-images.mjs |
| About stack — hero-1.webp | 1920 | calculated by sharp (fit: inside) | portrait; actual height ~2882 |
| About stack — hero-2.webp | 1200 | calculated by sharp (fit: inside) | portrait; actual height emitted by script |
| Nav logo | 110 | 110 | Logo is square (10000×10000 intrinsic); CSS sets height:110px; use display dimensions |

Actual gallery/about heights MUST be taken from sharp `.toFile()` output, not assumed. The convert-images.mjs script must emit these values into `src/data/photos.js` as `width` and `height` fields per entry.

### Rule 2: Gallery images must remain lazy-loaded

`loading="lazy"` is required on all gallery `<img>` elements. These are below the fold. Do not change to `loading="eager"`.

### Rule 3: Hero image is a video poster, not an img element

The hero LCP candidate is the `poster` attribute on a `<video>` element in `Hero.jsx`. There is no `<img>` for the hero. The LCP preload hint addresses this directly via `<link rel="preload">` in `index.html`. Do not add an `<img>` to the hero section.

### Rule 4: About background image has no img element

`cover-image.webp` is referenced only as a CSS `background-image` in `About.module.css`. It has no `<img>` element and receives no `width`/`height` attributes. The CSS path must be updated from `.jpg` to `.webp` but no other change is made.

### Rule 5: Preload hint syntax

Exactly one `<link rel="preload">` must appear in `index.html` immediately after `<link rel="canonical">`:

```html
<link rel="preload" as="image" href="/photos/barton-springs/hero-1.webp" fetchpriority="high" />
```

No `imagesrcset` attribute. No `type` attribute. Href must match the `poster` attribute on the `<video>` element in Hero.jsx exactly.

### Rule 6: CSS layout dimensions are unchanged

`About.module.css` declares `.imageStack img` with `width: 78%` and `aspect-ratio: 3 / 4`. These CSS rules are unchanged by this phase. The `width` and `height` HTML attributes coexist with these CSS rules — the browser uses the attributes for layout reservation before CSS loads, then CSS overrides the display size.

### Rule 7: Gallery CSS layout is unchanged

Gallery uses a CSS columns masonry layout (`columns: 3` on `.grid`). `.item img` has `width: 100%; height: auto`. These CSS rules are unchanged. The `width`/`height` HTML attributes on gallery images coexist with `height: auto` — the browser uses the intrinsic aspect ratio from the attributes to reserve vertical space in the column.
