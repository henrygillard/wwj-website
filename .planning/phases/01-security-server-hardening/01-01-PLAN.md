<objective>
Harden the Express server (`server/index.js`) against four classes of vulnerability: missing security headers, contact form abuse via flooding, HTML injection into outbound emails, and overly-permissive caching of static assets.

Purpose: Protects users (via security headers and XSS prevention in emails), protects the business (rate limiting blocks spam/abuse), and improves cache efficiency for hashed build assets.

Output: A rewritten `server/index.js` that installs and wires `helmet` and `express-rate-limit`, adds an inline `escapeHtml` helper, and configures `express.static` with a `setHeaders` callback. `package.json` gains `helmet` and `express-rate-limit` as production dependencies.

    SEC-01 — Helmet with CSP override: Add `import helmet from 'helmet'`. Call `app.use(helmet({ contentSecurityPolicy: { directives: { ... } } }))` immediately after `app.set('trust proxy', 1)`. The CSP directives must include: defaultSrc ["'self'"], scriptSrc ["'self'", "'unsafe-inline'"] (allows JSON-LD blocks), styleSrc ["'self'", "https:", "'unsafe-inline'"], fontSrc ["'self'", "https://fonts.googleapis.com", "https://fonts.gstatic.com"], imgSrc ["'self'", "data:", "https://wwj-video-bucket.s3.us-east-2.amazonaws.com"], mediaSrc ["'self'", "https://wwj-video-bucket.s3.us-east-2.amazonaws.com"], connectSrc ["'self'"], objectSrc ["'none'"], baseUri ["'self'"], formAction ["'self'"], frameAncestors ["'self'"]. The S3 domain in imgSrc and mediaSrc is mandatory — the video element loads from that bucket.

    SEC-02 — Rate limiter: Add `import { rateLimit } from 'express-rate-limit'`. Set `app.set('trust proxy', 1)` as the FIRST statement after `const app = express()` — before any middleware. Define `const contactLimiter = rateLimit({ windowMs: 15 * 60 * 1000, limit: 10, standardHeaders: 'draft-6', legacyHeaders: false })`. Apply it as the first argument after the path in `app.post('/api/contact', contactLimiter, async (req, res) => { ... })`. Do NOT apply it globally with `app.use()`.

    SEC-03 — HTML escaping: Add the `escapeHtml` helper function (covers &, <, >, ", ' — five replacements in that order) immediately after the imports, before `const app = express()`. Inside the contact handler, derive `safeName = escapeHtml(name)`, `safeEmail = escapeHtml(email)`, `safeInquiry = escapeHtml(inquiryLabel)`, `safeMessage = escapeHtml(message)` before constructing the email object. Use safe* variables in the `html:` field and in `replyTo:` and `subject:`. The `text:` field MUST keep the original unescaped values (name, email, inquiryLabel, message) — plain text is not HTML and escaping it would corrupt the readable email.

    SEC-04 — Cache headers: Replace `app.use(express.static(join(__dirname, '../dist')))` with `app.use(express.static(join(__dirname, '../dist'), { setHeaders(res, filePath) { if (filePath.includes('/assets/')) { res.setHeader('Cache-Control', 'public, max-age=31536000, immutable') } } }))`. The `filePath.includes('/assets/')` guard is mandatory — without it, index.html would be cached for a year, preventing users from seeing updates.

    Preserve all existing behavior: nodemailer transporter config, 400 validation for missing fields, 500 on mail error, SPA fallback route, PORT env var, console.log on listen.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → Express /api/contact | Untrusted user input (name, email, inquiry, message) enters the contact handler |
| Express → nodemailer HTML email | Composed HTML string is sent to the band's inbox — injection here is exploitable |
| Browser → Express static | Clients request static files; cache headers must be scoped to hashed assets only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Spoofing | X-Frame-Options / clickjacking | mitigate | helmet sets X-Frame-Options: SAMEORIGIN by default |
| T-01-02 | Tampering | MIME sniffing — browser overrides declared Content-Type | mitigate | helmet sets X-Content-Type-Options: nosniff by default |
| T-01-03 | Tampering | HTML injection via contact form name/email/message into HTML email | mitigate | escapeHtml() applied to all four user fields before HTML template construction |
| T-01-04 | Tampering | XSS via CSP bypass — inline scripts in response | mitigate | helmet CSP with scriptSrc restricted; 'unsafe-inline' allowed only for JSON-LD data blocks (no user-generated script paths exist) |
| T-01-05 | Denial of Service | Contact form flooding from single IP | mitigate | express-rate-limit: 10 requests per 15 minutes per IP; 429 on breach; trust proxy=1 for real IP on Heroku |
| T-01-06 | Information Disclosure | Referrer header leaks origin URL to third parties | mitigate | helmet sets Referrer-Policy: no-referrer by default |
| T-01-07 | Tampering | Protocol downgrade (HTTP instead of HTTPS) | mitigate | helmet sets Strict-Transport-Security: max-age=31536000 by default |
| T-01-08 | Tampering | index.html cached for one year — users miss content updates | mitigate | setHeaders guard checks filePath.includes('/assets/') before setting immutable cache header |
| T-01-09 | Spoofing | IP spoofing via X-Forwarded-For manipulation | accept | trust proxy=1 trusts exactly one hop (Heroku router); clients cannot inject extra hops from outside Heroku's network. Acceptable risk per Heroku docs. |
</threat_model>
